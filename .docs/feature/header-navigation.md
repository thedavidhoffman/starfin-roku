# Header Navigation

The top-level header keeps text labels beside matching monochrome icons: a house
for Home, magnifying glass for Search, gear for System, and person silhouette for
Account. Icons appear to the left of their labels. The icon and text are centered
as a pair within each button and use the same normal, focused, and active colors.
Each glyph is cropped to its visible artwork and displayed at a shared 22-pixel
height, close to the label's capital-letter height. Its width follows its shape.

The navigation glass and buttons are wider to preserve the original label
spacing. The glass remains centered on the screen, with the System and Account
dropdowns aligned to their buttons. Other uses of `HeaderButton` remain text-only
unless an `iconUri` is supplied.

The nine transparent white icon assets are generated by
`scripts/generate-header-icons.mjs` and tinted by the button at runtime.

The System dropdown uses sliders for Settings, a circled information symbol for
System Info, and a document with text lines for App Log. Its background grows
from 260 to 300 pixels, and the item buttons from 220 to 260 pixels, while its
left edge stays at the same position. System dropdown icons keep their individual
widths and are centered in a 30-pixel column after the 18-pixel item inset.
Every icon-bearing label begins 58 pixels from the item button's left edge.
Dropdown items without icons use the 18-pixel left inset. The icons share the
header glyph height.

The Account dropdown uses opposing horizontal arrows for Switch and an arrow
leaving a doorway for Logout. Both use the same 30-pixel icon column and the
same 22-pixel glyph height as the System dropdown. Its menu width stays at 260
pixels.

## Back and exit confirmation

Back from an open System or Account dropdown closes only the dropdown and returns
focus to its header button. Back from any header button with no dropdown open
shows an "Exit Starfin?" dialog above the header and current page.

Back from any Home item also opens the same exit confirmation, replacing the
previous immediate-exit behavior. Home emits a repeatable backSelected event;
MainScene handles both Home and header Back through one confirmation path.

The dialog offers Cancel and Exit, with Exit focused initially. Left and Right
move between the buttons. Cancel or Back closes the dialog and restores focus to
the Home item or header button that opened it. If Home rebuilt the originating
shelf while the dialog was open, its existing focusHome path restores available
Home focus. Restoration checks the saved node's current parent chain through its
original owner to MainScene: Roku can retain a valid `getScene()` on a detached
shelf, so that value alone does not establish that the node is still attached.
Exit signals MainScene.closeRequested; the existing main loop closes
the screen and ends the app. Back behavior on other pages and dialogs is unchanged.
MainScene owns exit routing; the dialog and content
own confirmation presentation and selection.
